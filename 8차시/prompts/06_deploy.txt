# 실습 6 — GitHub에 올리기 + Pages 켜기 (12분)  [4부]

## 전제
- gh auth status 에 Logged in (실습 4)
- 저장소 이름은 반드시 `아이디.github.io` (내 GitHub 아이디, 소문자)
  → 주소가 https://아이디.github.io 가 된다.
  다른 이름(예 mysite)이면 주소는 https://아이디.github.io/mysite/

## 6-1) 올리기 — 프롬프트 ("아이디"를 내 아이디로)
```
이 폴더를 git 저장소로 만들고 첫 커밋을 해줘.
그다음 gh로 내 GitHub에 "아이디.github.io" 라는 이름의
공개(public) 저장소를 만들고 push 해줘.
아이디는 gh auth status로 확인해서 정확히 써.
끝나면 저장소 주소와 홈페이지 주소를 알려줘.
```
- 승인 창: `gh repo create`, `git push` 는 밖으로 나가는 작업.
  저장소 이름과 --public 이 맞는지 읽고 Yes.
- 확인: 브라우저에서 https://github.com/아이디/아이디.github.io 를 연다.
  index.html 이 보이면 성공.

뒤에서 도는 명령 (참고용. 외우지 않는다):
```
git init
git add .
git commit -m "첫 페이지"
gh repo create 아이디.github.io --public --source=. --push
```

## 6-2) Pages 켜기
먼저 https://아이디.github.io 로 접속해 본다. 사용자 사이트(아이디.github.io 저장소)는
Pages가 자동으로 켜져 있는 경우가 많다. 1~2분 기다려 열리면 끝.

열리지 않으면 A 또는 B:

A. 웹에서 (눈으로 확인)
  저장소 페이지 → Settings → 왼쪽 메뉴 Pages
  → Build and deployment / Source: "Deploy from a branch"
  → Branch: main, 폴더: / (root) → Save
  → 1~10분 뒤 상단에 "Your site is live at https://아이디.github.io"

B. 말로 (Claude Code)
```
이 저장소의 GitHub Pages를 main 브랜치 루트(/)로 켜줘.
켜진 뒤 사이트 주소와 상태를 알려줘.
```
뒤에서 도는 명령 (참고용):
```
gh api -X POST repos/{owner}/{repo}/pages -f "source[branch]=main" -f "source[path]=/"
gh api repos/{owner}/{repo}/pages
```
({owner}/{repo} 는 현재 폴더의 저장소로 자동 치환된다)

## 6-3) 확인
- PC 브라우저: https://아이디.github.io
- 휴대폰: 같은 주소. 카드가 세로로 쌓이고 글자가 잘리지 않는가
- 옆사람 화면에서 열어 본다 → 남의 화면에서 열리면 진짜 공개된 것

## 반영이 안 될 때
- 보통 1~2분, 길면 10분. 강력 새로고침: Ctrl + Shift + R
- 저장소 → Actions 탭에서 배포 진행 상태(초록 체크 = 완료)
- 404가 뜨면 셋 중 하나:
  1) 저장소 이름이 아이디.github.io 인가 (소문자, 오타)
  2) index.html 이 저장소 맨 위(루트)에 있는가
  3) 저장소가 Public 인가

## 공개 전 마지막 점검
페이지를 처음부터 끝까지 읽으며 실명·소속·연락처·사진이 없는지 본다.
있으면 지우고 다시 올린다 (이력에는 남으므로 처음부터 넣지 않는 것이 원칙).

## 완료 기준
- [ ] https://github.com/아이디/아이디.github.io 에 index.html 이 보인다
- [ ] https://아이디.github.io 가 PC와 휴대폰에서 열린다
- [ ] 개인정보가 없다
