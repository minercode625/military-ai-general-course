[바꾸지 않는 줄 (오늘은 기본값)]
  EPOCHS = 3            # 데이터 전체를 몇 번 반복해 보여 줄지 (1~3 권장)
  LORA_R = 16           # 보조 다이얼의 크기 (8, 16, 32 ...)

[하는 일]
원래 다이얼 21억 개는 잠그고, 옆에 붙인 보조 다이얼(LoRA, 약 1%)만 돌린다.
369쌍을 8쌍씩 묶어 한 번 돌리고(1스텝), 3바퀴 = 141스텝.

[기대 출력]
  다이얼: 전체 2.09B개 중 학습하는 보조 다이얼 23.0M개 (1.10%)
  (unsloth 로고 글씨, 진행 막대 141/141, 스텝마다 loss 한 줄 — 숫자가 내려간다)
  학습 끝: 4.0분, 스텝 141개, 손실 처음 2.94 → 마지막 0.45
  GPU 메모리 최대 6.3 GB
  (손실 그래프)

[기록표]
  학습 시간(분)            :
  손실 처음 값 / 마지막 값 :        /
  그래프 모양 (하나에 O)   : 내려가다 평평해짐 / 들쭉날쭉 / 0 근처까지 떨어짐

[기다리는 동안]
탭을 닫거나 다른 셀을 누르지 않는다. 셀 왼쪽이 ■ 모양이면 돌아가는 중.
5분을 넘기면 손을 든다 (T4가 아니라 CPU로 돌고 있을 가능성 — 셀 1 첫 줄의 GPU 이름 확인).

[손실이 0.05 안팎까지 내려가는 이유]
오늘 데이터는 답 20개가 10번씩 되풀이되고 규정 답도 짧다. 외우는 것이 곧 목표라 손실이 0 근처에 붙는다
(T4 실측: 둘째 바퀴 평균 0.09, 셋째 바퀴 평균 0.05, 가장 낮을 때 0.006). 마지막 스텝의 0.45는 한 묶음이 튄 값이다 — 숫자 하나가 아니라 그래프를 본다.
답이 제각각인 실제 데이터에서 0.2 아래로 떨어지면 과적합(새 질문에 못 함)을 의심하고 에포크를 줄인다.

[팁 — unsloth 공식 가이드]
에포크 1~3. 학습률 2e-4, r 16~32에서 시작.
결과가 나쁘면 설정보다 데이터를 먼저 의심한다. 바꿀 때는 한 번에 하나만.
