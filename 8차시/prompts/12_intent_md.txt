# intent.md — 만들기 전에 적는다  [3부]

intent.md 는 만들기 전에 "무엇을, 왜, 어떤 제약으로" 원하는지 적어 두는 파일이다.
Anthropic 「AI-native SDLC 플레이북」(2026.8)에서 개발의 첫 산출물로 쓰는 이름.
CLAUDE.md 와 달리 자동으로 읽히지 않는다. "intent.md를 읽고"라고 말해야 한다.

## 1) Claude와 같이 쓰기 (직접 타이핑하지 않는다)
```
intent.md를 쓸 거야. 아래 다섯 칸을 하나씩 나에게 물어보고,
내 답을 정리해서 이 폴더에 intent.md로 저장해줘.
문제 / 제안된 결과 / 영향을 받는 사용자와 시스템 / 제약 사항 / 미해결 질문
```
→ 저장된 파일을 읽고, 틀린 곳은 말로 고친다.

## 2) 예시 (오늘 홈페이지용)
```
# Intent: 민트의 소개 페이지
작성: 민트. 상태: 초안.

## 문제
나를 소개할 주소가 없어서 매번 말로 설명한다.

## 제안된 결과
주소 하나를 열면 소개, 관심사 3개, 연락 링크가 보인다.

## 영향을 받는 사용자와 시스템
처음 만난 사람이 휴대폰으로 본다. GitHub Pages에 올린다.

## 제약 사항
index.html 하나. 실명, 소속, 연락처, 사진은 넣지 않는다.

## 미해결 질문
배경은 밝게 할까 어둡게 할까? 사진 자리에 무엇을 넣을까?
```

## 3) 계획 모드에 건네기
Shift+Tab 을 눌러 상태줄을 plan mode on 으로 바꾼 뒤:
```
intent.md를 읽고 구현 계획을 보여줘.
바뀌는 파일, 작업 순서, 확인 방법을 적어줘.
```
→ 계획을 읽고 고칠 곳을 말한다. 승인하면 만들기 시작.
  (계획 모드에서는 Claude가 파일을 읽기만 하고 바꾸지 않는다.)

## 참고
- 플레이북의 흐름: intent.md → spec.md → 계획 모드 → plan.md → 코드.
  오늘은 한 장짜리 페이지라 spec.md, plan.md 는 건너뛴다.
- 실습 5-1을 이 순서(1 → 3)로 시작해도 된다(선택).
  계획을 승인하면 05_homepage_build.txt 의 첫 프롬프트 없이 만들기가 시작된다.
