실습 7  파인튜닝 vs RAG — 같은 모델, 근거를 붙이면 (6분)  — 셀 8

[하는 일]
3차시 코드 그대로: 규정집(docs/mint_rules.txt)을 조항 31개로 자르고 → 숫자로(임베딩, e5-small) →
질문과 가까운 조항 3개를 찾아 → 규칙 4줄과 함께 프롬프트에 붙여 → 방금 학습한 같은 모델에게 묻는다.
규정 질문 6개(실습 1의 6~10 + 퇴직금)마다 답 셋과 "찾은 조항"이 나온다:
  [파인튜닝만] / [파인튜닝 + RAG] / [원래 모델 + RAG] (보조 다이얼을 잠시 뗀 공개 모델 그대로)
첫 실행은 임베딩 모델 내려받기로 30초쯤 더 걸린다. 약 1.5분.

[T4 실측 — 파인튜닝 + RAG]
있는 것: 호텔비 → "제15조에 따라 80,000원" (조항까지 고쳐짐). 자기계발비 → "제28조 연 500,000원" (부칙을 못 찾아 "올랐나"엔 답 못 함).
없는 것: 주차비 → "제21조 접대비 …" 동문서답, 육아휴직 → "제14조 2년" 지어냄, 퇴직금 → "제19조 …" 지어냄.
프롬프트에 "없으면 규정집에 없습니다라고만 답한다"가 있어도 파인튜닝된 모델은 "제N조에 따라 …"를 뱉는다 — 100쌍 전부 그 모양이었기 때문.
[T4 실측 — 원래 모델 + RAG] (같은 프롬프트, 보조 다이얼만 뗀 것)
숙박비 → "규정집 (1)에 따르면 … 80,000원" 맞음. 자기계발비 → "규정집에 없습니다"(부칙을 못 찾은 검색 실패).
주차비 · 육아휴직 · 퇴직금 → 셋 다 "규정집에 없습니다". 같은 규칙을 받고도 원래 모델은 "없다"고 하고, 파인튜닝된 모델은 지어낸다.

[기록표]
 질문                     | 파인튜닝만 | 파인튜닝+RAG | 원래 모델+RAG | 찾은 조항이 맞나 | 틀렸다면 검색 실패 / 생성 실패
 6 국내 출장 숙박비        |                   |             |                  |
 7 호텔비(다른 표현)       |                   |             |                  |
 8 자기계발비 작년 대비    |                   |             |                  |
 9 주차비(없음)            |                   |             |                  |
10 육아휴직(없음)          |                   |             |                  |
   퇴직금(없음)            |                   |             |                  |

[읽는 법]
조항이 엉뚱하면 검색 실패(주차비: 중식·자기계발비·접대비 조항이 왔다), 조항은 맞는데 답이 틀리면 생성 실패(3차시와 같은 구분).
있는 것은 RAG가 고친다. 없는 것은 모델의 습관이 결정한다 → "없다"고 답하는 예시를 학습 데이터에 같이 넣어야 한다(12_home.txt).
자주 안 바뀌는 것(말투 · 형식 · 절차)은 모델에 넣고(파인튜닝), 자주 바뀌는 것(가격 · 규정)은 검색으로 붙인다(RAG).
고르는 순서: 프롬프트로 되면 끝 → 문서를 알아야 하면 RAG → 그래도 말투 · 형식 · 작은 모델이 필요하면 파인튜닝.
